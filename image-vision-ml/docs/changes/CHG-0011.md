## CHG-0011 — Phase 4.1-Telemetry

**Timestamp:** `2026-10-22T20:28:22Z` (first completed development train-run)
**Phase:** Phase 4.1-Telemetry
**Type:** feature
**Status:** Verified

## Reason

The frozen Phase 4.1 experiment stored final metrics without a training-event log. Researchers needed genuine run identifiers, algorithm-specific diagnostics, historical playback, and a read-only API, without fabricating curves or reopening 2025 test labels.

## Previous behavior

`GET /training` reported telemetry unavailable. No `train-run` command. No `runs/` directories. The laboratory had no Training Runs tab.

## New behavior

Explicit CLI `train-run --telemetry` writes isolated run artifacts. Events are schema-valid JSONL with monotonic elapsed time. Persistence/seasonal record zero optimization iterations. Ridge records linear-system diagnostics without epoch curves. HGBR records `n_iter_` and post-fit `staged_predict` training MSE when measured. Read-only `/runs` APIs and a Training Runs UI provide timeline, charts, playback, and comparison. Frozen Phase 4.1 files remain byte-stable. Research flags stay false.

## Modified files

See front matter. Generated run artifacts live under gitignored `data/processed/ml/experiments/plovdiv_soil_forecast_baselines_v1/runs/`.

## Scientific impact

No change to frozen 2025 holdout findings (persistence strongest at h=1 and h=3; small Ridge skill at h=7). New validation MAE values on development runs are telemetry, not a restatement of those holdout tables. ERA5-Land modeled targets. `suitable_for_modeling=false`.

## Backward-compatibility impact

Existing experiment GET endpoints unchanged. Experiments with no runs return an empty list. No operational `/predict`.
