## Reason

Record Phase 3.3 work that is present in the working tree but was never given a change ID.

## Previous behavior

Satellite coverage, calibration conflicts, and modeling eligibility were less explicitly documented as task-specific readiness with separate scene-quality versus calibration status.

## New behavior

Temporal coverage reporting, calibration audit fields (`scene_quality_status` vs `calibration_status`), and task-readiness assessments. January 2025 valid-NDVI rejection remained a quality-control outcome, not a code defect. `suitable_for_modeling` was not weakened.
