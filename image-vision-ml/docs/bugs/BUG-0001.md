## Description

Expected: a CDS retrieve is complete only when the monthly file and the next-day 00:00 UTC boundary are non-empty recognised GRIB/NetCDF payloads.

Actual (historical report): a July 2024 boundary file could be zero bytes while the month was still treated as downloaded, so the official ERA5-Land daily total for 2024-07-31 could not be closed.

## Environment

- Python 3.14.4, rasterio/numpy not required for this path
- Dataset: `plovdiv_weather_2023_2025`
- Month: `2024-07`
- Files: `data/raw/weather/plovdiv_weather_2023_2025/hourly/2024-07.nc` and `2024-07.boundary.nc`
- Current sizes as of this documentation: 307000 and 72698 bytes (non-empty). Manifest `updated_at` `2026-10-22T04:18:22.156223+00:00`, status `downloaded`
- No credentials stored

## Reproduction

1. Write an empty `YYYY-MM.nc` or `YYYY-MM.boundary.nc`.
2. Call `month_integrity`.
3. Before the fix, an empty file could also be classified as `invalid_format` and block retry; a non-empty destination still must not be overwritten.

## Evidence

- `month_integrity` reasons `empty_hourly_file` / `empty_boundary_file` in `ml/ingestion/weather_download.py`
- Current July 2024 files are non-empty; the original zero-byte payload is not retained. This record is retrospective.
- A leftover `2024-07.download` (307000 bytes) is present beside `2024-07.nc` and was not deleted.

## Root-cause analysis

Empty CDS artefacts are not valid archives. The downloader also refused to replace any existing destination, including a zero-byte file, which prevented a clean retry. Current non-empty July 2024 files indicate a later data repair or re-download; that is not the same as a permanent code fix.

## Resolution

- Empty hourly files are flagged without being collapsed into `invalid_format`.
- `_commit_downloaded_file` unlinks a zero-byte destination and installs the new payload.
- Non-empty destinations still raise `WeatherDownloadError`.
- Existing July 2024 imagery/weather files were not overwritten by this change.

## Mathematical or scientific impact

A missing D+1 00:00 UTC boundary makes `precipitation_total_mm` and `evaporation_total_mm` for the last UTC day of the month null (`missing_boundary`). That is correct once emptiness is detected. NDVI, calibration, and satellite geometry were unaffected. If an empty boundary had been treated as success, daily precipitation for 2024-07-31 could have been wrong or silently missing.
