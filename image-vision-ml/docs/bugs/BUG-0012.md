## Description

Expected: `data_fingerprint.json` records the SHA-256 of the Phase 4.0 `features_daily.csv` used to train.

Actual: `features_daily_sha256` duplicated `source_fingerprints.daily_weather` (354,555 bytes, prefix `e475956c…`), which is `daily_weather.csv`, not the 2,602,708-byte features table.

## Environment

Experiment `plovdiv_soil_forecast_baselines_v1` after `prepare` at `2026-10-22T18:37:06Z`.

## Reproduction

1. Read `data/processed/ml/experiments/plovdiv_soil_forecast_baselines_v1/data_fingerprint.json`.
2. Compare `features_daily_sha256` with `source_fingerprints.daily_weather`.
3. Before the fix they were identical.

## Evidence

Pre-fix payload set `features_daily_sha256` from `fingerprints.get("daily_weather")`. Weather file size 354,555 bytes; features table size 2,602,708 bytes.

## Root-cause analysis

`prepare_experiment` reused the Phase 4.0 weather/soil source-fingerprint map and assigned the weather checksum to a features-table field. Training still used the joined features/targets/splits; the defect is provenance metadata, not leakage into model inputs.

## Resolution

`_data_fingerprint` now hashes `features_daily.csv`, `targets.csv`, `split_membership.csv` and `dataset_manifest.json`. The existing experiment file was rewritten at `2026-10-22T18:47:09Z`. Models, freeze, and 2025 test metrics were not refit.

Correct features checksum prefix: `e7f6f0745b97f8ac`. Targets prefix: `884e3d0731a833e5`.

## Mathematical or scientific impact

None for predictions or skill. Reproducibility metadata was wrong until repaired. Source weather/soil archives were not modified.

## Validation

`tests/test_soil_forecasting_experiment.py::test_data_fingerprint_uses_features_table_not_weather` passed. Full file 13 passed at `2026-10-22T18:47:21Z`.
