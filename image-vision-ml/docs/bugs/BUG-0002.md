## Description

Expected: a completed, checksum-matched ERA5-Land month is never silently replaced.

Actual: retries raise `Refusing to overwrite {filename}`. That is the intended behaviour for non-empty files.

The harmful case is only a zero-byte destination, which is `BUG-0001`, not this rule.

## Environment

Weather downloader in `ml/ingestion/weather_download.py`. No secrets stored.

## Reproduction

`test_checksum_mismatch_is_not_overwritten` writes a non-empty mutated NetCDF and expects `WeatherDownloadError`.

## Evidence

- `download_weather_month` skips complete checksum-matched months.
- `_commit_downloaded_file` refuses non-empty destinations.

## Root-cause analysis

Not a defect. Overwrite refusal protects validated weather archives.

## Resolution

No change to the non-empty overwrite rule. Empty-file replacement is documented in `BUG-0001`.

## Mathematical or scientific impact

None. Scientific precipitation math is unchanged.

## Validation

Existing overwrite tests remain the specification.
